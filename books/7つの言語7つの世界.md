#### Mixin
前提として、複数のクラスから継承を行う「多重継承」は複雑で問題が多いことが知られている。
PHPやJavaではインターフェースでこの問題を解決している。
Rubyではクラスの一部としてモジュールをMixin(混ぜ込む)ことによってこの問題を解決している。

以下がモジュールの例である。
```
module ToFile
	def filename
		"object_#{self.object_id}.txt"
	end

	def to_f
		File.open(filename, 'w') {|f| f.write(to_s)}
	end
end

class Person
	include ToFile
	attr_accessor :name

	def initialize(name)
		@name = name
	end

	def to_s
		name
	end
end
```

to_sメソッドはモジュールで使用されているが、実装はクラスで行われている。
つまり、to_sメソッドがどのような実装になっているかto_fは知らない。
Personクラスでもほかのクラスでもto_sメソッド（文字列を出力するメソッド）があればそれをファイル出力するのがto_fメソッドなのだ。

Rubyではインターフェースは存在しないので、暗黙的に行う。

ダックタイピングという言葉も紹介されていた。
「もしそれがアヒルのように歩き、アヒルのように鳴くなら、それはアヒルである」というように、オブジェクトの「型（クラス）」ではなく、「持っているメソッドや振る舞い」で判断するということを表現している。つまり暗黙的ということ。

ちなみに自分はあまりこの考え方が好きではない。

また、モジュールはincludeすればおわりという簡単さも重要である。

#### Enumerable Comparableモジュール
Rubyで最も重要なmixinとしてこの2つがあげられる。

Enumerableはクラス側で「each」を実装していれば、コレクション操作用のメソッドが使えるようになるモジュール。
例えば、mapメソッドやselectメソッドが使える。

Comparableはクラス側で「<=>」を実装していれば、大小比較用のメソッドが使えるようになるモジュール。
「<=>」は宇宙船演算子と呼ばれる。2つの値の大小等しいに応じて-1,1,0を返すメソッドである。

コードブロックを使わない場合

```

```

コードブロックを使うとファイルが自動的に閉じられるなど、リソースが自動的にクリーンアップされるので、安全で簡単なコードが実現できる

- Rubyの配列はスタックとしても使える。スタック以外に、配列で実現可能なよくあるデータ構造体を挙げよ。また、使用してみよう。

スタック
```
stack = []

# 要素の追加
stack.push("Book A")  # [ "Book A" ]
stack << "Book B"     # [ "Book A", "Book B" ]
stack.push("Book C")  # [ "Book A", "Book B", "Book C" ]

# 要素の削除
stack.pop
puts "現在のスタック: #{stack.inspect}" # => [ "Book A", "Book B" ]
```
配列の「push」メソッドと「pop」メソッドを使用して、後入れ先出し（LIFO）のデータ構造を表現できる。

キュー
```
queue = []

# 要素の追加
queue.push("Book 1") # [ "Book 1" ]
queue << "Book 2"    # [ "Book 1", "Book 2" ]
queue.push("Book 3") # [ "Book 1", "Book 2", "Book 3" ]

# 要素の削除
queue.shift
puts "現在のキュー: #{queue.inspect}" # => [ "Book 2", "Book 3" ]
```
配列の「push」メソッドと「shift」メソッドを使用して、先入れ先出し（FIFO）のデータ構造を表現できる。
