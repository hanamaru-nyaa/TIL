# トランザクション分離レベル

## 目的
トランザクション分離レベルの概念を理解する

## 前提知識
### トランザクションとは
データベースに複数の処理が発生した時におかしくならないようにするための処理単位のこと。

トランザクション内の操作が「すべて実行される」か、「まったく実行されない」ことが保証できる。

### ACID特性とは
トランザクション処理に欠かせない特性

- 原子性（Atomicity）
- 一貫性（Consistency）
- 分離性（Isolation）
- 永続性（Durability）

今回扱うのは、ACID特性の中の分離性である。

分離性とは、複数トランザクションは互いに影響を与えないという特性。

同時に処理した時もごちゃごちゃにならずに分離されているように処理される。

## 分離レベルはなぜ必要？
トランザクションに完璧な分離性を持たせると、処理時間が長くなってしまうという欠点がある。

そこで、どれくらい厳密にトランザクションを分離するかを決めるのが分離レベルの役割になる。

## 分離レベルの種類
トランザクション分離レベルは以下の4つである。

[処理速度が遅い][安全]

- SERIALIZABLE
- REPEATABLE READ
- READ COMMITTED
- READ UNCOMMITTED

[処理速度が速い][危険]

### SERIALIZABLE
トランザクション実行時にトランザクションで読み取るすべての行に共有ロックをかける。

分離レベルがSERIALIZABLEのトランザクションA,Bがあるとする。

先にAがデータを読み取ると、Bは同じデータに対して読み取りは可能だが、更新や追加はできない。

先にAがデータを更新や追加をしたら、Bは読み取りもできない。

### REPEATABLE READ
最初に読み取った値をずっと参照する。つまり、別のトランザクションの更新も反映しない。

ファントムリードが発生する。

ファントムリードとは・・・

データの追加や削除など、データ件数が変更された場合に別のトランザクションから更新後の値が見えてしまう現象。

MySQLでは、MVCC（Multi-Version Concurrency Control）という技術によってファントムリードは解決されている。

MVCCとは・・・

トランザクションにバージョンを付与することで競合を回避させる技術。

MySQLでの実装

すべてのテーブルのすべてのレコードに自動的に以下のカラムを追加する。

- DB_ROW_ID・・・行ID
- DB_TRX_ID・・・最後に更新したトランザクションID
- DB_ROLL_PTR・・・過去の値を持つレコードデータへのポインタ

未来のトランザクションIDが入っていたらレコードをDB_ROLL_PTRからポインタをたどって参照する。

### READ COMMITTED
コミットされた変更は読み取れる。

ファントムリードが発生してしまう。
ファジーリード（ノンリピータブルリード）が発生してしまう。

ファジーリードとは・・・

データの中身の更新が途中で発生すると、データの読み取りに矛盾が生じること。

### READ UNCOMMITTED
コミット前の変更も読み取れる。

ファントムリードが発生してしまう。
ファジーリードが発生してしまう。
ダーティーリードが発生してしまう。

ダーティーリードとは・・・

別トランザクションでコミットされていない変更も読み取れてしまう現象。

### 分離レベルのデフォルト
MySQLのデフォルトはREPEATABLE
PostgreSQLのデフォルトはREAD COMMITTED

## 使い方
トランザクション開始前に分離レベルを指定する必要がある。

MySQLの場合
```
mysql> SET TRANSACTION ISOLATION SERIALIZABLE;
mysql> START TRANSACTION;
```

LaravelのDBファサードを使用する場合
```
<?php

use Illuminate\Support\Facades\DB;

DB::statement('SET TRANSACTION ISOLATION LEVEL READ COMMITTED');

DB::beginTransaction();
try{
	// 処理
} catch(\Exception $e) {
	// 処理
}
```
